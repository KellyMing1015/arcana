# Arcana

一个网页塔罗抽牌与 AI 解读原型。你可以提问、长按牌面洗牌、滑动切牌、抽取单牌或牌阵，随后在单屏结果页阅读解读，并进入独立聊天页围绕同一副牌继续追问。结果页的解读卡片和聊天消息区各自滚动，输入框始终固定在对话页底部。

## 首次运行

在这个文件夹打开终端，依次运行：

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

启动网站：

```sh
.venv/bin/python app.py
```

如果 VPS 上已经有 `.venv`，直接启动即可。`app.py` 会检查 Flask、邮箱密码加密和环境变量读取所需的运行依赖；发现缺失时，会自动按 `requirements.txt` 安装后继续启动。因此日常从 GitHub 拉取更新时，不需要额外增加安装命令。

在浏览器打开 `http://127.0.0.1:4173/`。点击左上角 **ARCANA 设置**，可以进入“供应商”“用户信息”和“历史牌阵”；首页右上角显示“未登录”或当前账号昵称。供应商页面填写名称、API Base URL、API Key，再点“获取模型”从列表选择模型；如果供应商不支持模型列表，也可手动填写模型名。用户信息页面可以保存多人资料，并用每行右侧开关选择本次解读使用的用户；全部关闭时不会发送个人信息。再次运行时，只需执行启动命令。结束服务时按 `Control + C`。

请用上面的本地网址打开，不能直接双击 `index.html`：`file://` 页面无法连接 Flask 解读接口。

登录后，供应商配置和解读用的多人档案会同步到账号；整个设置数据包使用服务器密钥加密后存入 `arcana.db`。注册账号时会自动建立一条与账号昵称同名、默认启用的用户资料，让第一次解读就能归档到云端；其他资料可以之后再补充。浏览器仍保留当前账号的本地副本以供页面使用，退出登录时会清除这份账号缓存。首次使用此版本登录时，如果账号还没有云端设置，会自动上传当前浏览器已有的设置。账号密码只保存 bcrypt 哈希。未登录仍可正常添加本地设置、抽牌和解读，但不会写入云端历史。

## 可选：服务端默认配置

如果更希望把密钥放在后端，可以复制 `.env.example` 为 `.env`，填写三个值：

```text
LLM_BASE_URL=https://你的中转站地址/v1
LLM_API_KEY=你的密钥
LLM_MODEL=中转站支持的模型名
ARCANA_SECRET_KEY=一串足够长且随机的服务器密钥
ARCANA_COOKIE_SECURE=0
```

`LLM_BASE_URL` 填到 `/v1` 为止，程序会自动补上 `/chat/completions`。未在页面选中供应商时，网站使用这组服务端配置。`ARCANA_SECRET_KEY` 同时用于保护登录 Session，并派生账号设置的数据加密密钥；VPS 上必须填写、不能公开，投入使用后也不能随意更换，否则旧的加密设置将无法读取。`ARCANA_COOKIE_SECURE` 本机 HTTP 调试保持 `0`；VPS 配好 HTTPS 后改成 `1`。`.env` 和 `arcana.db` 都已被 `.gitignore` 排除，不会上传到 GitHub。修改 `.env` 后需要重启 Flask。

注册接口会校验邮箱格式和唯一性。真正向邮箱发送验证码或验证链接还需要接入邮件服务商；当前版本没有发送验证邮件。

## 历史记忆

登录后，开启个人信息并使用有 `id` 的用户档案，塔罗师会在开始新解读时读取该账号、该档案最近 30 天内的最多 30 条云端历史，按时间从新到旧排列。只传日期、问题、牌名与正逆位、100 字以内的总结，不传完整解读。没有登录、没有档案编号、个人信息关闭或没有符合条件的历史时，解读 Prompt 保持原样。

记忆只在首次解读前读取一次；继续追问始终沿用这份快照，当前牌局保存后也不会加入自己的记忆。历史放在 `<reading_history>` 数据块中，字段里的标签字符全部转义，不能闭合数据块。`prompts/memory.md` 规定如何使用这些历史：首次解读不主动提起过去，追问时只在相关且合适时自然提起。

本地体验：打开 `http://127.0.0.1:4173/`，注册或登录本地账号，开启个人信息，完成一次解读并确认已保存云端历史，再重新开始一局。新解读及其追问会带上上一局的历史。首次解读会悄悄参考历史，因此不会显示“已读取记忆”的文字，也不要求它主动说“上次”。本地数据库与 VPS 数据库独立；刚下载项目时，需要在本地先积累一条历史。

## 塔罗师的便签

便签是账号下每个用户档案各自的长期背景。一条对应一件正在进行的事，由模型起 2–4 字的主题名，同一件事的进展合在一条里。最多 20 条、每条 300 字，所有正文合计不超过 3000 字。登录后，在“设置 → 用户信息”选择用户，就能查看“塔罗师的便签”和最后更新时间；可以编辑主题及正文、删除单条或全部清空，手工修改会标记“你编辑过”。没有便签时不添加任何额外 Prompt。首次解读和追问都可带上便签，追问会重新读取最新内容，让编辑和删除及时生效；最近牌局的历史记忆仍沿用首次读取的快照。

提炼另用一组后端模型配置，在 `.env` 填写以下三项后重启服务。它们可以填写你选择的 OpenAI 兼容中转站和模型，程序不会自动使用普通解读供应商来提炼：

```text
ARCANA_MEMORY_MODEL_BASE_URL=https://你的中转站地址/v1
ARCANA_MEMORY_MODEL_API_KEY=便签模型的密钥
ARCANA_MEMORY_MODEL=便签模型名称
```

缺少任意一项时，跳过提炼，正常抽牌、解读和追问不受影响。首次解读及之后每轮追问完成后都会后台提炼；该轮用户发言少于 5 个字符时不调用模型。每次输入只包含当前便签、用户删除过的内容、本次用户发言及理解短回答所需的塔罗师问句、同一账号及档案最近 10 条历史的问题和日期，不传牌面、总结或解读全文。同一账号及档案的提炼串行执行，已经在排队的请求合并为一次、采用最新会话版本；不同牌局会保留独立的发言来源，一起提炼，不会互相覆盖任务。会话版本记录在 SQLite；新解读开始时只补偿先前失败的提炼，不再补提普通未完成牌局。后台工作不会阻塞解读文字。

便签默认不改，只记录能帮助未来解读的长期事实，提炼规则放在 `prompts/profile_extract.md`。模型返回 `{"changed":true,"notes":[{"topic":"转行","text":"你在准备转行。"}]}`，`notes` 是完整集合，代码在事务中整体替换；没有变化返回 `{"changed":false}`。`changed:false` 或完整内容一致时，便签编号和更新时间保持不变。单条正文超过 300 字时截断；整组仍超过 20 条或 3000 字时，保留原便签并标记 `limits_exceeded`，不静默丢掉整条便签，由后续重试要求模型合并压缩。格式或模型请求失败也保留失败状态，下次最多重试一次；诊断只记录固定结果分类，不保存模型原始输出。

用户删除过的内容单独记录，旧会话不能把它重新写回来；用户删除后又明确重提才允许写回。模型不能删掉或改写用户手工编辑的内容，只能在用户明确补充新事实时保留原文并追加。给手动便签补充正常提炼后的文字时，模型会额外返回 `evidence` 用户原话；程序核对这些原话确实来自手动编辑之后的发言，证据不保存到便签中。被保护规则拒绝的提炼保留有限重试状态，不再把遗漏误记成整理完成。后台提炼期间的手动编辑、删除、关闭个人信息优先于模型结果。关闭用户开关时不读便签，也不提炼。升级主题便签版本时会自动清空旧版便签一次，账号、资料、供应商与历史牌阵保留；之后重启不会再次清空。

本地体验：在 `http://127.0.0.1:4173/` 登录并启用个人信息，提问或追问时描述持续几周的处境，例如“我在准备转行做产品，还没离职，下班后在赶作品”。回复完成后等待后台模型返回，重新进入用户信息页查看主题便签；继续补充同一件事的新进展，应融进同一条便签。普通短回复和一次性小事不要求新增便签。若未配置专用模型，该区域会保持空白。便签保存在当前服务器的 `arcana.db` 中，本地和 VPS 数据库各自独立；GitHub 不存用户数据。

自动检查无需调用真实模型或 API Key：

```sh
.venv/bin/python -m unittest discover -s tests -v
```

为避免测试导入应用时初始化真实数据库，完整测试建议指定一个临时启动数据库（每项测试仍使用自己的临时库）：

```sh
ARCANA_DATABASE=/tmp/arcana-test-bootstrap.db .venv/bin/python -m unittest discover -s tests -v
```

前端慢网与图片重试检查（需要 Node.js）：

```sh
node --test tests/test_frontend_reliability.mjs
```

GitHub 的 `Arcana tests` 工作流会在上传代码和提交合并请求时自动运行上述后端、前端及脚本语法检查；使用临时数据库和模拟模型，不需要任何真实 API Key，也不部署 VPS。

追问发给模型时会清理首轮的总结指令和总结段落，只改消息副本；每轮隐藏提示只发给模型，不保存到用户历史。追问流中的 `【总结】` 及后文会被过滤，首次解读及云端历史总结保留原样。

## 更新与连接排查

Prompt 在服务启动时读取。VPS 完成 `git pull --ff-only` 后，需要重启现有的 Arcana 服务，再开始新牌局；仅刷新网页不会更新后端 Prompt。首次解读使用 `base.md + reading.md`，追问使用 `base.md + conversation.md`；`system.md` 是旧版参考，修改它不会改变当前解读。请先确认 VPS 工作目录没有尚未保存的修改，再拉取；如果提示分支有分歧，先检查并保留改动，不要强行覆盖。

供应商在开始返回文字之前明确报 502、503 或 504 时，程序等待半秒并最多重试一次。密钥、余额、限流错误及已经开始的文字流不自动重试。缺少完成标志的断流、达到回复长度上限、内容被模型拦截都视为失败：不保存半截解读，不消耗追问轮次，不触发本轮便签提炼。服务器日志只记录固定错误分类和 HTTP 状态，不记录密钥或对话正文。

图片预加载只在明确下载失败后换地址重试，不会因为下载超过四秒重复请求。抽牌动画仍限制等待图片的时间，因此慢图不会把页面一直卡住。首页的应用脚本带版本号，避免上线后继续命中旧脚本缓存；之后修改 `app.js` 时请同步更新 `index.html` 中的脚本版本号。

## 文件说明

- `index.html`、`styles.css`、`cards.js`、`app.js`：抽牌页面、78 张牌的资料和交互。
- `assets/cards/`：从 Wikimedia Commons 下载的 78 张高清牌面，以及每张图的来源链接。牌面原画由 Pamela Colman Smith 绘制；该文件分类页将素材标为公有领域。网页使用 960 像素宽的 WebP 版本，以缩短加载时间。牌背仍使用原来的 Arcana 设计。
- `assets/ui/card-back-cream-magic-v3.png`：奶油魔法风卡背的高清源图；网页实际使用从该源图等比生成的 `card-back-cream-magic-v3-mobile.jpg`，降低手机端洗牌动画的下载和解码压力。
- `assets/ui/rabbit-single-color.png`、`assets/ui/dove-single-color.png`：首页使用的单色兔子与鸽子装饰。
- `scripts/fetch_card_art.py`：需要重新获取图片时运行；使用 `requirements.txt` 中的 Pillow。
- `settings.js`：页面中的供应商和用户信息设置，数据保存在浏览器 localStorage。
- `auth.js`：登录注册页面、账号菜单、本地历史迁移和云端历史页面。
- `app.py`：Flask 网站、账号与历史接口、首次解读和继续追问接口。
- `profile_memory.py`：按账号及用户档案隔离的便签、待提炼会话和后台模型任务。
- `arcana.db`：首次启动自动创建的 SQLite 数据库，保存在服务器本地，不进入 Git。
- `llm.py`：向 OpenAI 兼容格式的中转站发起请求；密钥只保存在后端环境变量中。
- `prompts/base.md`、`prompts/reading.md`、`prompts/conversation.md`：共用人格、首次解读和继续对话的规则。
- `prompts/memory.md`：有历史时追加的记忆使用规则；`prompts/system.md` 保留为旧版参考。
- `prompts/profile_extract.md`：仅从用户原话提炼便签的规则。

`POST /api/models` 使用供应商的 `/models` 接口拉取模型名。`POST /api/reading` 接收 `question`、`spread`、`cards`、`userInfo`，以及可选的 `provider`。三牌阵只调用一次模型：模型先选择六种解读框架之一，前端再更新牌位标题。首次解读会返回 `conversationId`。`POST /api/follow-up` 使用这个编号读取完整历史，并允许每次请求传入新的供应商配置；一副牌最多追问 8 轮。用户也可以通过 `POST /api/conversation/end` 提前结束本次对话。对话暂存在 Flask 进程内，服务重启或超过 6 小时后需要重新抽牌。所有文字都通过 SSE 流式返回；请求开始前的错误返回 `{"error":"具体原因"}`。

账号接口包括 `POST /api/register`、`POST /api/login`、`GET /api/me` 和 `POST /api/logout`。`GET/PUT /api/account-data` 负责读取和更新当前账号的加密供应商与用户资料。云端历史接口包括 `POST /api/readings`、`GET /api/readings` 和 `POST /api/readings/migrate`。所有账号数据接口都从 Session 中取得当前用户编号，客户端不能指定其他用户。

便签接口：`GET /api/profile-notes?profile_id=...` 查询，`PATCH/DELETE /api/profile-notes/<id>` 编辑或删除单条，`DELETE /api/profile-notes` 清空。修改请求都带 `profile_id`；所有便签接口均要求登录，按当前账号和档案双重限定记录。数据库新增 `profile_notes`、`profile_notes_removed`、`profile_memory_sessions`，启动时自动建表，无须手动改数据库。
